## 2. 依赖安装

提交包根目录为解压后的 `zhenji-package/`，不附带 `.venv`。在该目录新建环境时可用以下任一种方式；2026-10-14 的独立回放核验只复用了现有依赖，**未**在干净环境重跑安装：

```sh
# 方式 A：requirements.txt（宽松版本）
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt

# 方式 B：requirements.lock.txt（本机实际锁定版本，推荐复现一致）
uv venv .venv
uv pip install --python .venv/bin/python -r requirements.lock.txt
```

`requirements.txt` 内容为 `numpy pandas scipy h5py matplotlib scikit-learn obspy pytest mcp==2.2.0`。

提交包不包含研发机的 `.venv`、`node_modules`、AGH 构建产物或 `vendor/pnpm-10.34.5/`。无 Key 记录回放需要先安装 Python 依赖；真实 Agent 执行还需要 AGH 依赖与本地 CLI 构建。独立环境建议使用 AGH `package.json` 指定的 pnpm 10.34.5，在 `vendor/agnes-harness/` 安装锁定依赖并核查 `@agnes/cli` 的 `build:local` 构建脚本；此处只是待核查的安装建议，不声称完整干净安装已经通过。第 3 节的 `../pnpm-10.34.5/` 命令属于研发机历史路径，不能直接当作提交包自带入口。

## 4. 无 Key 回放已保存运行（不调用模型、不取数）

`GET /api/evidence/<run_id>` 直接读取已落盘记录，不调用模型、不访问网络、不需要模型 Key。提交包将精选记录放在 `replay/runlog/<run_id>/`；启动时必须显式设置 `RUNLOG_DIR`。2026-10-14 已在独立解压目录中核实首轮、反馈证据和三分量波形能够读取，不依赖研发目录中的 `main/runlog/`。

### 4.3 离线开关语义

`EQ_STRICT_OFFLINE=1` 表示**禁止联网补齐新观测材料**；它本身不等于“不会尝试模型调用”。页面 `health` 把 `strict_offline`（观测离线）与 `model_available`（模型是否可用）分开返回。回放路径两者都不触发。

## 8. 失败处理

- 运行失败：保留 `result.json` 的 `status/failure_kind` 与 `cleanup_status.json`，失败不会用历史结果顶替。受控超时示例见 `delivery/remediation-2026-10-12/evidence/agh_resource_integration.json` 的 `timeout` 场景（`failure_kind=timeout`，资源仍被回收）。
- 离线材料缺失：离线模式下缺材料会明确抛 `OfflineMaterialMissing`（“离线模式：材料缺失……不联网补齐”），见 `delivery/remediation-2026-10-12/evidence/remediation_probe.json` 的 `A_first_round_uses_optimization_driver` 明细。
- 取数被拒：范围外候选、超出候选上限或本轮禁止新增取数时，守卫在发 HTTP 之前即拒绝（`http_issued=false`）。
- 进程残留：历史旧驱动 `main/agent_run.mjs` 曾在 `/tmp/eq-main-*` 留下 daemon/worker，应按各自 `AGH_HOME` 用官方 CLI `daemon stop` 逐个清理，**不要全局杀进程**（见 `delivery/remediation-2026-10-12/HANDOFF.md` §7）。
- 归档注意（已修）：`main/agent_run_optimization.mjs` 现在清理前用 `node:sqlite` 的 `VACUUM INTO`（失败退回 `PRAGMA wal_checkpoint(FULL)` + 复制）生成一致的 `native_sessions.db` 快照，包含 WAL 中未 checkpoint 的行；免费回归见 `tests/test_native_archive.py`。历史旧链目录里早先复制的主文件副本可能仍为空表，如实注明即可，不要伪造恢复。
