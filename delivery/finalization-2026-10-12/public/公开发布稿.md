## 标题

**震迹：围绕观测证据开展智能核查，改变条件后继续复核**

副标题：地震候选事件智能核查

## 正文

一段地震波形能不能拿来分析，往往不是一句话能回答的：要同时看通道是否健康、采样率与频带是否支持目标方法，还要知道自动到时在不同分析条件下是否稳定。这些其实是几个不同的问题，混在一起就会得出含糊的结论。

震迹把它们拆开复核。你用自然语言提出一个具体问题，例如“这段观测能不能用来做 1–12 Hz 的 P/S 拾取？”，并填写 UTC 时窗、台站或区域、目标频带。工作台会围绕这些条件开展智能核查，取得公开观测并分析波形，再核对建议是否得到证据支持。结果里可以查看核查结论、观测波形、已发生的核查过程，以及结论适用的条件。

更关键的是“改条件再复核”：当你排除一台站、更改分析目标，或把到时检查频带收紧到 3–12 Hz，系统会生成一条与上次核查关联的新记录，默认沿用已保存的波形，并按当前条件重新检查。两次记录分开保存，条件变化与结果可以对照。

震迹严格区分“方法适用性”和“到时诊断稳定性”：前者是通道、采样率与频带是否满足方法输入条件，后者是自动到时在已检查条件下是否可复现。页面也保留证据不足、结果待确认和核查未完成等状态；智能建议未通过核对时，明确展示观测核查结果。

在工作台点击“查看核查示例”，可以免费查看已完成的核查及条件复核记录。填写新条件后，可先免费确认条件，也可直接开始核查；智能核查按实际用量计费，标准核查免费。震迹用于专业核查，不测定震级、不做定位或预警；满足方法输入条件也不等于已经确认地震或识别 P/S。

## 三项实际能力

1. **观测与分析**：智能核查选择所需观测，完成到时检查与稳定性诊断；页面显示已经发生的核查步骤和结果。
2. **条件变更后复核**：排除或恢复台站、更改分析目标、调整到时检查频带后生成关联记录；默认沿用已保存的波形，并展示前后条件及实际检查结果。
3. **可核对的证据与状态**：核查建议与观测证据相互核对，结果适用范围随结论一起展示；证据不足、未完成及建议未获支持的情况均保留。

## 技术来源与真实执行链（供评审核对）

当前产品页面以“智能核查”“核查记录”“核查过程”等用户语言展示结果。底层真实执行链仍使用 Agnes Harness（AGH）；产品文案调整没有改变模型调用、观测或验证证据。

```
用户任务（自然语言 + UTC 时窗 + 范围）
        │
        ▼
AGH（Agnes Harness）：会话 / 规划 / 工具调用 / 资源与预算守卫
        │  实际模型：DeepSeek deepseek-flash（经本地回环桥接）
        ▼
MCP 专业工具：list_candidates / acquire_station / run_onset_check /
              run_stability_check / get_evidence / task_status / exclude_observation
        ▼
公开观测（EarthScope FDSN）与本地数值计算（ObsPy 等）
        ▼
确定性规则验证：字段 / 条件 / 范围 / 证据引用 / 停止依据
        ▼
结果（复核完成 / 合法未知 / 规则后备 / 执行失败）
        ▲
用户反馈（排除台站 / 换目标 / 换网格）—— 生成子运行回到新条件
```
