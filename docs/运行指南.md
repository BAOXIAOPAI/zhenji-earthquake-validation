# 运行指南

本项目提供本地工作台、专业核查工具与保存的真实核查记录。记录位于 `replay/runlog/`，可离线查看结论、工具过程和三分量波形。下文路径均以项目根目录为基准。

## 环境

| 组件 | 已验证环境 | 用途 |
| --- | --- | --- |
| Python | 3.12.14 | 本地服务、观测读取与数值计算 |
| Node.js | 24.15.0；AGH 要求 ≥24.10 | 新智能核查的 AGH 会话与模型连接 |
| pnpm | 10.34.5 | AGH 依赖与本地构建 |
| Python 依赖 | `requirements.lock.txt` | 固定数值与接口组件版本 |

记录回放的独立目录验证使用已有 Python 依赖，检查了服务接口、保存记录与观测读取。验证范围见[验证结果](./验证结果.md)。

## 安装 Python 依赖

在项目根目录执行：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
```

## 启动记录回放

在项目根目录执行：

```sh
RUNLOG_DIR="$PWD/replay/runlog" EQ_STRICT_OFFLINE=1 .venv/bin/python main/server.py 8791
```

打开 `http://127.0.0.1:8791/`。需要使用其他端口时，修改命令末尾的端口号。

`main/start.sh` 提供相同的服务入口，需要 `/bin/zsh`：

```sh
RUNLOG_DIR="$PWD/replay/runlog" EQ_STRICT_OFFLINE=1 ./main/start.sh
```

`RUNLOG_DIR` 指定包内记录路径。`EQ_STRICT_OFFLINE=1` 将工作台设为离线模式，禁止获取新观测，并关闭页面中的新模型核查入口；查看保存记录不调用模型或读取 API 凭据。

## 查看示例

页面包含“核查工作台”“核查记录”“使用说明”。工作台默认展示保存的核查示例，可查看结论、波形、分析依据和条件对比。在核查记录中选择另一条记录，可查看对应结果。

| 记录 | 内容 |
| --- | --- |
| `r-e2e8419bf299785d` | 真实首轮核查，检查三分量输入条件和自动到时证据 |
| `r-3ae9c6948c2f8967` | 将诊断频带收紧到 3–12 Hz 后复核，复用首轮波形 |

也可通过只读接口查看：

```sh
curl http://127.0.0.1:8791/api/runs
curl http://127.0.0.1:8791/api/evidence/r-e2e8419bf299785d
curl http://127.0.0.1:8791/api/evidence/r-3ae9c6948c2f8967
curl http://127.0.0.1:8791/api/waveform/r-e2e8419bf299785d/409dfad13970
```

波形接口读取该记录保存的 MiniSEED，返回 Z/N/E 分量的显示包络与计算产生的到时标记。页面显示的是保存观测，不是实时监测数据流。

## 开始新核查

新智能核查需要 AGH 运行环境、DeepSeek API 凭据和联网观测服务。AGH 源码位于 `vendor/agnes-harness/`，其依赖版本由 `pnpm-lock.yaml` 固定，本地构建入口为 `@agnes/cli` 的 `build:local`。

使用表中版本的 Node.js 和 pnpm，在项目根目录执行：

```sh
cd vendor/agnes-harness
pnpm install --frozen-lockfile
pnpm --filter @agnes/cli build:local
cd ../..
```

### 配置模型凭据

在项目目录的上一级创建本机文件 `deepseek_model.txt`，用文本编辑器将 `Key:` 与自己的 DeepSeek API 密钥写在同一行。服务检查该文件是否可读；执行智能核查时，模型桥接从该文件读取密钥。

例如，项目位于 `zhenji-earthquake-validation/`，密钥文件与这个目录同级。文件不属于项目源码。保存后，在项目根目录设置读取权限：

```sh
chmod 600 ../deepseek_model.txt
```

AGH 核查与服务启动检查使用这一固定路径。`PROVIDER_KEY_FILE` 仅由单次模型脚本 `main/one_shot.mjs` 支持，不能替代工作台智能核查的默认配置。

### 配置费用记录

费用上限与用量估算配置位于 `analysis/model-budget.json`，调用记录保存到 `runs/model-budget-ledger.json`。启动智能核查前，两者都需存在且能够读取。

首次为本应用配置新的调用账户、尚无费用记录时，可执行以下命令创建记录文件；命令使用排他创建方式，文件已存在时会停止，不覆盖原内容：

```sh
mkdir -p runs
.venv/bin/python -c 'from pathlib import Path; Path("runs/model-budget-ledger.json").open("x", encoding="utf-8").write("{\"entries\":[],\"halted\":false}\n")'
```

已有调用记录应继续使用原文件。智能核查在每次请求前预留费用，并在收到用量后更新记录；模型服务商的实际账单由其计费系统提供。

### 启动联网核查服务

在项目根目录执行以下命令，使用独立目录保存新结果；端口 8792 可与前述只读工作台同时使用：

```sh
RUNLOG_DIR="$PWD/runtime/runlog" EQ_OUTPUT_DIR="$PWD/runtime/output" EQ_STRICT_OFFLINE=0 .venv/bin/python main/server.py 8792
```

打开 `http://127.0.0.1:8792/`。可先访问 `/api/health` 检查 `model_available`；该检查只检查本机配置，不调用模型或读取密钥内容。只有开始智能核查或智能反馈才会调用模型。标准核查不调用模型，但可获取公开观测。

填写问题、台站、UTC 时窗与频带后，可直接点击“开始智能核查（计费）”或“开始标准核查（免费）”。系统先检查输入；“确认条件（免费）”为可选操作，不获取观测。完成后可调整条件并复核。

本项目的执行证据来自保存的真实核查，独立回放检查验证这些材料能够从包内读取。该检查没有执行新环境依赖安装、AGH 重建或新的模型任务。
