## 边界：证据不足与结束条件

以下场景使用确定性规则测试，不调用模型或获取新观测。结果见 `evidence/validation-cases.json`。

| 测试 | 结果 |
| --- | --- |
| 排除范围内唯一观测，禁止新增取数 | 接受 `pick_unknown`，`audit_outcome=legal_unknown`，`can_finish=true` |
| 范围内仍有可取候选，尚未取证即声称范围耗尽 | 拒绝，`can_finish=false`，原因 `empty_scope_but_actions_remain` |
| 引用尚未计算的到时 | 证据引用验证失败 |
| 声明虚构的参与范围 | 范围验证失败 |
| 缺失合法结束依据 | 结束依据验证失败 |
| 引用已排除的观测 | 证据有效性验证失败 |

这些结果验证规则对范围、证据和结束条件的检查语义，不代表真实模型在相同场景下的总体表现。

## 失败：超时与不一致结论

受控超时测试采用替代上游模型传输，实际运行 AGH 与 MCP 生命周期。结果见 `evidence/execution-lifecycle.json`：

| 场景 | 结果 |
| --- | --- |
| 正常执行 | 会话完成，工具调用记录保存，所属运行资源回收 |
| 4000 ms 受控超时 | `status=failed`、`failure_kind=timeout`，结束处理完成，资源回收 |
| 并行会话隔离 | 另一会话的 PID 与连接保持不变 |

该组 8 项检查全部通过；上游传输为受控替代，不能作为真实模型任务的证据。

另有三条真实模型反馈：`r-2365883191ac74a8`、`r-8f2eb7e2a2e7333f`、`r-8c01734ee9f1903a`。三条反馈实际执行了请求的诊断网格，但模型把到时证据不足混入输入适用性判断。验证器拒绝这些模型主张，记录 `model_claim_accepted=false`、`fallback_used=true`，并保存原主张及拒绝原因。其 `status=succeeded` 表示会话执行完成，与模型结论是否被接受是两个字段。

三条记录保存在 `replay/runlog/`，父记录为 `r-40183b72e23b844f`；该父记录不在随附的五条回放记录中。
