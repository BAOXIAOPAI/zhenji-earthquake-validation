## 1. 最终呈现目标

项目统一名称：**震迹**。副标题：**基于Agnes Harness的地震候选事件智能核查Agent**。

主介绍建议：**让AI主动取证、调用专业分析工具，并在你改变条件后继续复核。**

评委应能快速看懂：用户核查的具体问题、Agent实际做了哪些动作、结果对应哪些观测和条件、用户变更条件后系统如何重新核查。首页先呈现这些信息，完整技术细节通过证据和说明入口展开。

本轮设计确定采用“浅色科研工作台＋深蓝品牌栏＋蓝绿强调”的方向。用真实数据、明确的信息层级和条件前后比较形成亮点，沿用现有HTML/CSS/JavaScript。一次做好工作台、记录回放与作品说明三个视图。

实现遵循用户指定的[Karpathy Guidelines](/Users/baoxiaopai/.codex/plugins/cache/openai-curated-remote/andrej-karpathy-skills/1.0.0/skills/karpathy-guidelines/SKILL.md)：每个改动对应本方案的具体任务，先解决真实展示缺陷，沿用现有接口，只增加必要的薄适配。

## 3. 实施边界与当前缺口

当前产品为main/start.sh→main/server.py→main/static，默认端口8791。prototype/start.sh及8765入口是旧原型，不能继续作为新README的主入口。最终说明使用相对路径和实际验证过的命令。

优先修正下列展示缺陷：

- 首页标题仍偏“离线任务验证”，反馈静态说明仍写“不调用模型”，与已接收AGH反馈相矛盾。

## 4. UI信息架构与具体行为

### 4.1 页面结构

主导航：**核查工作台 / 运行记录 / 项目说明**。旧实验对照保留为“历史实验资料”次级入口，离开默认主视图，明确版本与用途。

工作台桌面文字线框：

    顶部：震迹｜地震候选事件智能核查Agent｜AGH标识｜运行状态
    导航：核查工作台 / 运行记录 / 项目说明
    ┌──────────────────┬─────────────────────────────────────────┐
    │ 任务与当前条件     │ 当前核查结论＋完成/未知/后备/失败状态       │
    │ 问题、UTC、台站    ├─────────────────────────────────────────┤
    │ 方法目标、频带     │ 同run真实波形＋简明质量/诊断信息           │
    │ 样例/新任务操作    ├─────────────────────────────────────────┤
    │ 高级参数折叠       │ AGH真实工具时间线                         │
    │                  ├─────────────────────────────────────────┤
    │                  │ 改条件再复核＋首轮/当前条件对比            │
    └──────────────────┴─────────────────────────────────────────┘

桌面任务栏约320px，其余为结果区；内容最大宽度1440px。窄屏转为单列，顺序为任务→结论→波形→过程→反馈→详情。

### 4.2 默认入口与任务卡

首次打开提供两个清楚的入口：**查看已验收AGH示例**、**创建新核查**。默认可先浏览已验收记录；明确标“真实AGH运行回放”及执行日期。加载示例只读数据，不自动执行新任务。

验收示例固定为已接收父子链：首轮r-e2e8419bf299785d、反馈r-3ae9c6948c2f8967。可切换首轮/反馈记录。新核查模式默认Agent；规则复核作为明确的辅助模式，不能把规则执行显示成Agent。

任务卡显示问题、UTC时窗、台站范围、方法目标、目标频带；时间明确UTC，不静默转换为北京时间。目标频带、到时方法频带、诊断网格分开标注。高级区保留手填范围、模式、现有注入演示选项，不把所有参数一次性堆在首屏。

按钮建议：填写示例→免费解析任务→开始AGH核查。解析成功显示“系统理解的任务”，并注明此步骤未调用模型；输入改变后解析状态同步失效。新核查按钮旁说明使用模型额度，不能页面加载即调用。

### 4.3 结论与状态

主结论用现有中文statement/映射，不在前端重新科学判决。当前示例可显示“满足三分量拾取的输入条件”，另列“到时诊断尚不足以确认可复现触发”。两个不同字段分开表达。

| 状态 | 主显示 | 依据 |
| --- | --- | --- |
| 正常有效交付 | 复核完成＋本轮结论 | 执行成功、模型交付通过/实际规则来源 |
| 合法未知 | 复核完成·当前证据不足 | audit=legal_unknown，解释范围或停止依据 |
| 模型被拒且规则后备 | 已使用规则后备 | fallback_used/model_claim_accepted，保留原主张与拒绝原因 |
| 执行失败/超时 | 本轮执行失败 | status/failure_kind/cleanup；不能用旧结果占位 |
| 历史记录 | 真实运行回放·日期 | 持久run_id及实际来源，不显示为正在实时执行 |

数值false、0、空scope与缺失值分别处理，不能用truthy默认值抹掉。task_completed旧字段表示所问结果是否确定，结合audit呈现“复核完成但结果未知”。

主卡只放结论、短依据、当前参与范围、诊断提示、下一步。原模型JSON、完整limitations、source SHA、内部run_id放详情；不把被拒主张当主结论，也不把一项到时诊断分歧泛化为整个任务失败。

### 4.4 真实波形与专业证据

至少展示验收示例的一张同run真实波形图，支持查看该站Z/N/E组件。优先复用已有绘图/波形读取代码，从已落盘MiniSEED读取，补一条受限只读可视化接口即可。接口按run_id和该run的candidate_id解析文件，不接受任意路径。

图上标台站、分量、时窗/相对秒轴和归一化说明。到时标记只能来自该run的实际结果；缺结果不画，算法触发不能标成确认P/S。已排除站图仍可查看，但标“已排除，不参与当前结论”。派生/人工注入数据有来源标识。

绘图不取新数据、不运行新科学分析、不修改原文件；显示缓存放单独目录。品牌装饰曲线和线框不能替代实测波形。若通道独立归一化，说明它用于形态观察，不作跨站幅值比较。

简明证据区显示输入条件、当前实际诊断参数和稳定性结果。实际配置数由保存结果计算；不足有效配置时不能因spread=0显示“稳定”。AR-AIC等方法实际频带与用户网格分别披露。

### 4.5 AGH过程与条件前后比较

完成后，用真实tool_calls显示时间线：候选发现、观测获取、证据读取、到时诊断、稳定性诊断、完成检查。可展开原工具名、参数、结果、时间和来源。

前置条件守卫标“系统应用用户条件”，数值验证标“专业规则验证”，不要全部称为模型自主决策。固定工具用途说明可以帮助阅读，不编造Agent心理过程或隐藏思考文本。

当前产品未提供逐工具实时流：运行中先显示真实“AGH会话执行中”，完成后加载实际时间线。无需为视觉效果开发新流式服务；禁止假百分比、虚构逐站进度或伪装模型打字。

反馈设置三类明确动作：排除/恢复台站、切换方法目标、选择现有许可诊断网格。目标频带修改单列高级区。默认禁止补取，实际新任务模型/规则来源和费用性质清楚标注。

展示“首轮条件→本轮改动→当前条件与结果”。由父子证据实际比较，结论不变也说明哪些检查重算、哪些观测复用；不强迫出现改善。验收例重点展示网格变化、同一波形来源、新取数0及当前诊断。

### 4.6 运行记录、说明与下载

运行记录列问题、时间、来源、状态和父子关系，支持查看已完成与失败记录。详情使用持久evidence接口；不能用进程内track_id或LAST预览当重启后回放。原始run_id可复制，但不当页面主标题。

项目说明页用简短问题价值、已实现能力、AGH流程图、数据/工具来源与如何运行。下载提供由保存记录形成的报告与证据摘要，注明run_id和当前条件；导出不得把被拒答案包装为模型通过。

main目前未完整提供用户报告下载，若需补，只用已有task/state/validation/cost生成Markdown/JSON；PDF主项目说明另行制作。无需新报告生成Agent。
